# Decisions

How to use: the decisions of each component are the "Rules" and "Decisions" sections of its brief in `docs/PRD.md` (each rule carries its status tag). This file holds the decisions that span components, the dependency status, and the list of proposals the owner rejected. The agent reads this file and the component's brief before coding, and updates this file whenever a decision is made. A DEFAULT or OPEN item is never changed on the agent's own initiative (see `docs/OPEN_ISSUES.md`).

## 1. Cross-cutting requirements (owner)
1. STAGE 1 = A LOT OF DATA: all the Daf Yomi data on the Hub is used at home. SMALL-DATA READINESS is a LATER rehearsal stage (the work data is about one tenth of it): gates and defaults must stay sensible on a small set, rehearsed at home with the Subsampler `work_like` preset, but it is not a blocker for stage 1.
2. UNATTENDED RUNS: no operator during a run. Resume, logs to file, graceful time cap, exit codes.
3. NO ADMIN RIGHTS on the closed machine: virtual environment and per-user installs only, no system changes.
4. ONE OPERATOR: the owner (a programmer) runs everything alone on the closed machine. Messages, reports and docs must be clear and easy.
5. OUTSIDE FIRST: everything must work at home at the level of the real system before the move inside.
6. TWO LENSES FOR SUCCESS: the automatic test decides; the owner's own listening can reveal practical failure.
7. TASK FACTS: Hebrew only (language fixed); only the domain jargon changes between datasets; labels are treated as gold; the metric is WER; timestamps and special punctuation do not count in the final result.
8. FINAL MODEL FORMAT UNKNOWN: an export layer is required.
9. Report sensitivity is not a concern for now.
10. AGENT VERIFICATION (owner): the coding agent must run the unit tests of every component and, after that, run an end-to-end smoke run on tiny synthetic data with the tiny model. The artifacts of that run (reports, metrics file, model folder) are produced only to prove that the whole chain works.
11. Parallel runs must be a simple, TESTED switch, sequential by default.
12. EVERY change, however small, must be tested and verified to work before it is reported as done. Changes to interfaces, keys or files are proposed first (CLAUDE.md rule 3).
13. The report content (attributes, look, hint thresholds) is expected to be adjusted together with the agent after the owner sees the first real output.
14. USAGE HEADER (owner): every script and document the agent writes starts with a concise "How to run" section with an exact command and an example (CLAUDE.md section 9).
15. COMPONENT MAP (owner): a concise summary document of every component and its use, kept up to date by the agent (docs/COMPONENTS.md, CLAUDE.md section 10).
16. INTERNAL AGENT AT THE WORK SITE (owner): there is an internal agent on the closed machine; it is much weaker than Claude but can help. All documents (CLAUDE.md, COMPONENTS.md, TROUBLESHOOTING.md, RUNBOOK.md) must therefore be explicit, short and self-contained, with exact commands, so that a weaker agent can follow them. The same rules (diagnose first, smallest fix, no interface changes) apply to it.
17. REPRODUCIBILITY EXPECTATION: the same seed gives the same result on the same machine; results are not guaranteed bit-identical across machines, CPUs or core counts, so exact numbers are not compared between home and work. This is written into TROUBLESHOOTING.md.
18. BOOTSTRAP FIRST (owner, definite): before any component is built, the agent creates the requirements and environment files, initializes the git repository (`git init`) for version control, and runs the clean-environment install test at home. Every component task then ends with a commit.

## 2. Global decisions (owner-locked unless marked DEFAULT)
1. Pipeline order: DataSource, Splitter, TextNormalizer, SampleFilter, Subsampler, ModelLoader and FeaturePipeline, TrainerCore, Evaluator, then search, selection, registry, export, report. RunManager and Orchestrator wrap everything.
2. Offline by default. The pipeline never downloads anything. Only the standalone home-side tools use the network (DECISION: the ModelLoader loads local folders only, even when online mode is on).
3. CPU only. The machine must stay usable: `train.cpu_threads` is limited (DEFAULT half of the cores).
4. Data: at home all of the Daf Yomi data on the Hub is used (stage 1). The work data is about one tenth of that (rehearsed later with the Subsampler `work_like` preset).
5. Splitting is by group (content, for example the lesson `entry_id`), not by speaker. Test is never touched by subsampling in `train_only` scope. Ratios 80/10/10 are DEFAULT.
6. Two texts per sample: `train_text` (gentle cleaning, punctuation kept) and `eval_text` (aggressive cleaning, punctuation removed). WER is computed on `eval_text`. Each eval profile has a version; results of different versions are not comparable.
7. Timestamps: v1 strips timestamp tokens only. There is no need to deal with timestamps in the transcript. `keep` is a documented later extension.
8. SampleFilter: structural rules apply to all splits, quality rules to Train only (DEFAULT). Report mode is the default. Clips longer than the Whisper window are removed by the filter; the FeaturePipeline never truncates audio and FAILS if a longer clip arrives. Labels longer than the model limit are removed with a report and a gate.
9. Models: phase 1 validates the pipeline with a small OpenAI Whisper model; the ivrit-ai large-family models are a later phase run on the owner's own machine. The language is Hebrew only and is set from Config.
10. Training: unit is steps; only Val loss during training; checkpoints, resume, early stopping and an optional time cap; full fine-tuning by default; no LoRA and no `peft` in v1.
11. Search: Optuna is approved only as long as it helps; DEFAULT search over `learning_rate` and `grad_accum_steps` only; Val loss as the objective with pruning; finalists retrained on the full data and judged by WER on Val; sequential by default with a simple, tested switch for parallel trials.
12. Evaluation: corpus WER primary, CER secondary, our own implementation (no `jiwer`, never `evaluate.load`); paired bootstrap over groups with a lenient level of evidence (DEFAULT 90 percent, one-sided); a listening list for the owner; no weighting of error types.
13. Selection: Val decides; Test is evaluated once for the winner; "the baseline stays" is a legitimate outcome (exit code 0); a winner that Test does not confirm is flagged, not dropped.
14. Registry: numbered immutable entries, model card, checksums, index, a test-set usage counter. Exporter v1: Hugging Face format only plus the interface.
15. RunManager: numbered experiment folders (no timestamps in names), full config stored read-only, parent and diff, nothing deleted automatically, heartbeat lock, all reports written by the RunManager.
16. Orchestrator: one `run` command, stage commands, completion markers, stop at the first failure, fixed exit codes, graceful interrupt, sleep prevention on Windows, `smoke`, `benchmark`, `check`, `report`, `config-docs`.
17. Python 3.12 is the DEFAULT version, to be confirmed by the clean-environment install test.
18. Version control: `git init` at the bootstrap step; every component task ends with a commit.
19. Python version (O1, owner approved 2026-10-04): 3.12 stays. The clean-environment install test with Python 3.12.14 on Windows 11 (CPU only) passed, offline install and `pip check` included. The Python version of the closed machine is still UNKNOWN: ask the manager once, then run `python tools/fetch_wheels.py --python-version X.Y` (with a Python X.Y) to prove the stack installs on it.
20. Audio and parquet libraries (O9, owner approved 2026-10-04): soundfile and pyarrow. mp3 read and decode works on Windows (libsndfile 1.2.2), tested on synthetic files only; the first check on real Daf Yomi audio is a separate task.
21. Resampling and numpy (O36, owner approved 2026-10-04): scipy (`resample_poly`) and numpy, both listed in requirements.txt.
22. Package and command-line name (O62, owner approved 2026-10-04): `stt`.
23. Source layout (owner approved 2026-10-04): `src/stt/` with one subfolder per component, created when that component is built. Run and test with `PYTHONPATH=src` (no packaging, no new dependency): `set PYTHONPATH=src` in cmd, `$env:PYTHONPATH="src"` in PowerShell, then `python -m stt ...`; tests run with `python -m unittest discover -s tests` (the test files add `src` to the path themselves).
24. Test runner (owner approved 2026-10-04): unittest. No pytest dependency.

Short paths on Windows (owner approved 2026-10-04): the project and its `.venv` live at a short path such as `C:\stt` (40 characters or fewer) because Windows without long-path support fails to install torch in a deep folder, and enabling long paths needs admin rights. Documented in docs/RUNBOOK.md (first install step) and docs/TROUBLESHOOTING.md (Installation).
26. Data scope and split (O7, O42; owner approved 2026-10-04, based on the real-data check of Step 0c): the official `eval` split is NOT used as the Test. Train and eval are pooled and split by `entry_id`. Evidence: all 326 `entry_id` values of eval also occur in train (100% overlap), so the official eval is not held out by lesson.
27. Timestamp tokens (owner approved 2026-10-04): every label of the Daf Yomi data contains Whisper-style tokens such as `<|0.44|>` (2 to 28 per label). They are stripped from BOTH `train_text` and `eval_text` (consistent with decision 7 of section 2).
28. SampleFilter duration rule (owner approved 2026-10-04): kept. In the Daf Yomi data the "longer than the window" part never triggers (no clip is longer than 30 s; CORRECTED 2026-10-04 after the full C1 load: 8552 of 8723 clips are 30 s and 171 are shorter, down to 2.95 s; the earlier 50-row sample showed only 30 s clips), and it protects the work data.
29. Text characters (O25; owner approved 2026-10-04): geresh and gershayim (`׳`, `״`, for example in `כו׳`) stay in `train_text` and are dropped in `eval_text`; brackets and the ellipsis follow the O25 DEFAULT (remove the bracket characters, keep the content).
30. Single creator (fact, Step 0c): the Daf Yomi data has ONE creator ("zisman"). A Test split by `entry_id` therefore measures generalization to unseen lessons, NOT to unseen speakers.

C3 Splitter design decisions (made while building C3; they add details to the brief and need your approval where they add a key or a field): (a) two NEW config keys: `split.predefined.source_map` (source split name -> split name, for example `eval: test`; default empty) because `predefined` needs a way to map names, and `split.speaker_column` (a key of `extra`; default none) so that the report can say how many speakers are shared between splits; (b) one NEW result field: `SplitResult.dropped_overlap` (samples removed by `on_overlap: drop_from_train`), next to `dropped_guard`, so that the hard check "union equals input" stays exact; `SplitResult.data_fingerprint` is the fingerprint of the input and `SplitResult.fingerprint` identifies the split itself (assignments plus data); (c) `grouped_ratio` is a seeded greedy assignment (seeded stable group order, each group to the split furthest below its target), and fails when a requested ratio is missed by more than `split.ratio_tolerance`; for `hash_group` the deviation is only reported as a warning; (d) the oversized-group gate: a group is oversized when its share is above the smallest ratio plus `split.ratio_tolerance`; (e) for `time_block` the hard check "no group in two splits" is replaced by the guard gap (a recording is cut into blocks by design); (f) a saved split is never overwritten (a new `split.version` is the only way), `split.reuse: false` with an existing version FAILS; (g) a saved split whose data fingerprint differs FAILS for every mode, including `hash_group` (create a new version; the old groups keep their splits there by construction); (h) the missing names of `predefined` (for example `val`) are carved from the FIRST name by group, in proportion to the ratios; (i) `split.seed` falls back to `runtime.seed` through `resolve_seed`; (j) the speaker line of the report states that the Test does not measure generalization to unseen speakers whenever the speakers are shared between splits (true for the single-creator Daf Yomi data).

C2 TextNormalizer design decisions (made while building C2; they add details to the brief and need your approval where they add a key): (a) three NEW config keys, because rule 5 says every character list and pattern lives in Config: `text.punctuation.space_chars` (characters replaced by a space instead of removed; DEFAULT the Hebrew maqaf, as the brief says), `text.unicode.invisible_chars` (the invisible and direction-control characters that `unicode_clean` removes; DEFAULT zero-width, direction-control, soft hyphen, byte order mark, Arabic letter mark) and `text.timestamp_pattern` (DEFAULT `<\|(\d+(?:\.\d+)?)\|>`, one capture group with the seconds); (b) the DEFAULT punctuation list is a general set: `. , ; : ! ? …`, quote and geresh variants (`" ' “ ” ‘ ’ ׳ ״`), maqaf, hyphen, en dash, em dash. 37. C5 ModelLoader design decision, the Protocols of the loaded objects (owner delegated the choice to the agent on 2026-10-05; the brief left them OPEN). Options considered: (A) small Protocols with only what the FeaturePipeline, TrainerCore, Evaluator and SampleFilter wiring need, and an OPAQUE model object; (B) hand out the raw Hugging Face objects typed as `Any`: the least code, but Hugging Face types leak into high-level code and nothing documents what later components may call; (C) a full facade that wraps the model, the extractor and the tokenizer (forward, generate, save, freeze): the cleanest on paper, but it duplicates the Hugging Face API, is large, and would be redesigned when TrainerCore and the Evaluator are written. CHOSEN: A. `FeatureExtractor` has `sampling_rate`, `window_seconds`, `num_mel_bins` and `extract(audio, sampling_rate) -> float32 (mel bins, frames)` (it refuses another sampling rate and audio longer than the window, so nothing is truncated or converted silently); `LabelTokenizer` has `max_label_tokens` (the decoder limit, 448 for the OpenAI models), `encode_label(text)` (prefix tokens start, language, task, no-timestamps, the text, end), `count_tokens(text)` (text tokens without special tokens) and `decode(ids, skip_special_tokens)`; `LoadedModel.model` is typed `object` and only the adapter modules of the trainer and the evaluator look inside it (they may import torch and transformers; high-level code may not). Other details: (a) the sampling rate, window and mel bins are read from the extractor, the label limit from the model config (`max_target_positions`), never hard-coded; (b) `make_token_counter(tokenizer)` returns `tokenizer.count_tokens` as a plain `Callable[[str], int]` for the composition root to pass to the SampleFilter; (c) the Hugging Face adapter is imported lazily by the registry factory, so `import stt.modelloader` does not import torch; (d) the tokenizer is loaded with `clean_up_tokenization_spaces=False` (the default would strip spaces before punctuation when decoding, which corrupts Hebrew output); (e) an English-only model is detected from the vocabulary size 51864 in `config.json` before anything is loaded, an unsupported language from the missing `<|code|>` token; (f) `model.path` has no existence check in the Config schema, so the loader can give the specific fix (copy the folder, or run `tools/fetch_model.py`); (g) the language and task are written into `generation_config` and `forced_decoder_ids` is cleared so that the two settings are the only source; (h) `tools/make_test_model.py` builds the test model with 4-dimensional weights and the real vocabulary (3.9 MB, stored in `tests/assets/tiny_whisper`; random weights, seed 0).; (i) `.gitattributes` marks `tests/assets/**` as binary so the stored test model stays byte-exact on every machine (owner approved 2026-10-05; verified with a fresh clone: all 8 files have the same checksum).
38. C4 FeaturePipeline design decisions (owner delegated the technical choices on 2026-10-05; made while building C4). OPTIONS for the feature array and the collator output, and why the choice. The feature array in `FeatureExample` is (1) a plain float32 numpy array (mel bins, frames) [CHOSEN: no framework in the data type, small, directly storable as `.npy` for the cache, and `torch.from_numpy` is free], (2) a torch tensor (a torch import in the data type, so high-level code would depend on torch), or (3) nested lists (slow and large). The collator output is (A) a dict of torch tensors `{"input_features": float32 (batch, mel, frames), "labels": int64 (batch, longest label)}` with -100 padding and the leading decoder start token removed [CHOSEN: this is exactly what the Hugging Face `Seq2SeqTrainer` feeds to `model(**batch)`, the model builds the decoder input by shifting the labels and adding its own start token, and the brief puts the collator in the Hugging Face adapter], (B) a frozen dataclass `Batch` (pure, but the trainer would convert it back to a dict), or (C) numpy arrays converted by the TrainerCore (keeps torch out of the collator, but the brief says the collator lives in the adapter and the batch format is a Hugging Face concern). Other decisions: (a) NEW keys `features.shuffle` (DEFAULT false) and `features.seed` (DEFAULT none = `runtime.seed`), needed for the brief's acceptance test 7 (seeded order when shuffling is enabled); (b) `FeaturePipeline.build_collator()` creates the collator and reads the decoder start token id from the model's own configuration (an adapter may look inside the opaque model object); (c) the audio reading and conversion is an `AudioReader` Protocol with one adapter module (`audio_adapter.py`: soundfile and scipy), injected for tests, imported lazily; (d) the report counts resampled and downmixed samples from the file HEADERS, so building the report decodes no audio; (e) the cache key is the sample id, the audio path and the size and modification time of the audio file, inside a folder named after the extractor signature (its numbers plus the hash of the features of a fixed 1 s tone), so a changed extractor or audio file is never served from a stale file; (f) `features.num_workers` means threads that fill the cache (processes are avoided because of Windows spawn, O2); (g) the label-length distribution counts label ids including the 4 prefix tokens and the end token, because the limit applies to the ids; (h) a window limit has a tolerance of 1 ms.
39. C6 TrainerCore design decisions (made while building C6; they add details to the brief; the points marked NEW need your approval). OPTIONS considered for the Trainer's best-model handling: (A) the Hugging Face built-in (`load_best_model_at_end`, `save_total_limit`): needs every evaluation step to be a save step and gives no control over `min_delta`, the stop reason or what stays on disk, so the brief's defaults (evaluate every 50, save every 100) would not work; (B) the built-in early-stopping callback: same requirement; (C) OWN bookkeeping in a small callback and a pure `EvalMonitor` (CHOSEN): a checkpoint is forced at every new best Val loss, at every stop and at the end, only the latest and the best are kept, and the stop reasons are the brief's four. Other decisions: (a) NO new config key (the keys are exactly those of the brief); (b) NEW typed additions to the brief's objects: `TrainRequest.source_config_ref` (optional, written into `pipeline_model_info.json` for the ModelLoader; the RunManager will pass the config or diff path), `TrainResult.seed`, `TrainResult.history` is a tuple, `TrainResult.best_val_loss` may be None (no evaluation happened, for example a time cap before the first one; then `best_step` is the step of the latest checkpoint), `TrainTimings` is the type of `timings`, `StepMetrics.train_loss`, `learning_rate`, `grad_norm` and `eta_sec` may be None, and `TrainerConfigError` (exit code 2) is a subclass of `TrainerCoreError` (exit code 4) so that the Orchestrator can map both exit codes; (c) a metrics record is written at every log step and one more at every evaluation (the evaluation record carries the latest train values), so a step can appear twice in `metrics.csv`; (d) `seconds_per_step` is the mean of the training steps since the previous log record with evaluation and saving excluded, `eta_sec` is that mean times the remaining steps; (e) the time cap counts per call (a resume starts a new count) while `elapsed_sec` is cumulative; (f) the resume check compares the model name, the freeze policy, every hyperparameter (the learning-rate schedule depends on `max_steps`) and the data sizes, not the intervals; (g) a stop for any reason saves a checkpoint, so a stopped run can be resumed; (h) the returned model folder is built by COPYING the weights and settings from the best checkpoint and a FIXED list of tokenizer and feature-extractor files from the base model folder (no private access to the loaded tokenizer, nothing unexpected in the folder); (i) the datasets are read in the training process (0 data-loader workers, fixed in the adapter; O2 and Windows spawn); (j) the Trainer's own console and progress printing is removed, the sinks write the console line; (k) a metrics sink that fails never stops the training (a warning once); (l) the NaN guard checks the logged loss and gradient norm, the Val loss and the weights before each save; (m) an early stop on the first evaluation is read as: the best Val loss is the first evaluation and the patience ran out (the first evaluation always counts as an improvement, there is no best yet).

41. C7 Evaluator design decisions (made while building C7; they add details to the brief; the points marked NEW need your approval). ### 5.3 Pitfalls learned (do not repeat)
1. Line endings of stored test assets: with autocrlf a fresh clone changed `tests/assets/tiny_whisper/tokenizer.json`; `.gitattributes` (`tests/assets/** binary`) fixes it, and `config.json` had to be re-stored with `git add --renormalize` because the repository held a converted copy. Verified: a fresh clone has identical checksums for all 8 files. The release manifest (`tools/make_manifest.py`, not built yet) depends on byte-exact files.
2. A docstring that contains a backslash sequence such as `\|`, `\s` or `\v` becomes an invalid or wrong escape: make such a module docstring a raw string (`r"""`) or avoid the backslash. Run the tests with `python -W error::SyntaxWarning -m unittest discover -s tests` to catch it.
3. Shell pitfalls: a long `python - <<'EOF'` here-document that contains many quotes or Hebrew can fail with "unexpected EOF"; write such a script to a file with the Write tool and run it. A stray `cat >> /dev/null;` in front of a here-document swallows it. Hebrew in the Windows console needs `PYTHONIOENCODING=utf-8` (or `sys.stdout.reconfigure(encoding="utf-8")`).
4. pydantic: a `dict` field with a default does NOT merge with a partial YAML override (the other defaults vanish). The pattern used for `text.profiles` (two fixed profiles) and `filter.rules` (overrides only, defaults in the rule registry) avoids it. In `--set`, lists must be JSON text (`--set 'split.names=["a","b"]'`); the C0 parser was deliberately left as it is.
5. transformers 5.x: `from_pretrained(..., dtype=torch.float32)` (not `torch_dtype`); `AutoTokenizer` gives `WhisperTokenizer`; `tokenizer.set_prefix_tokens(language="he", task="transcribe", predict_timestamps=False)` produces the label ids `[50258, 50279, 50359, 50363, ..., 50257]` (start, he, transcribe, no timestamps, text, end); decoding with the default `clean_up_tokenization_spaces` would corrupt Hebrew (it is set to False); a damaged `model.safetensors` raises `SafetensorError`, which is not an `OSError`, so the loader catches `Exception`; `WhisperFeatureExtractor` returns `(80, 3000)` for any clip up to 30 s.

### 5.5 Conventions of the code base (so new components look the same)
Package `stt` in `src/stt/<component>/`, run with `PYTHONPATH=src`. Each component has: `config.py` (a `SectionModel` subclass for its own section, frozen, unknown keys forbidden, a DEFAULT in every Field description), `types.py` (frozen dataclasses and Protocols), `errors.py` (one error class, with the exit code in its docstring: config errors 2, data errors 3), a registry class (`name -> factory`, no if/else on names, unknown names fail and list the registered ones), adapter modules for torch, transformers, pyarrow, soundfile or scipy (the only modules allowed to import them), and `__init__.py` re-exporting the public names. Sections are registered by the composition root with `SectionRegistry({...})`; the config loader is never edited. Each component also gets `configs/<name>_default.yaml`, `tests/test_<component>.py`, an entry in docs/COMPONENTS.md and a numbered design-decision item in DECISIONS.md section 2. Unit-test count at this point: 277, about 26 seconds (the model tests load the stored tiny model).
