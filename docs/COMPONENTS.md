# Component map

How to use: one entry per component. The agent writes or updates the entry at the end of every component task; the whole file is checked at the end of the project. Entries below hold the planned purpose and config keys extracted from the PRD. The "How to use" line is filled in with the real command or call and one working example when the component is built. Status values: not built, built, verified.

## C0 Config
- Status: built (wave 1); `mypy --strict` is not installed here, so it was not run
- Purpose: Load, merge, validate and freeze all settings into one typed, read-only `AppConfig` object.
- How to use (project root, PowerShell; set `$env:PYTHONPATH = "src"` once per window):
  ```
  python -c "from pathlib import Path; from stt.config import load_config, dump_config; print(dump_config(load_config(Path('configs/base.yaml'), overrides=['runtime.seed=7'], target_environ={})))"
  ```
  Output: `runtime:` then `online: false` and `seed: 7`. In code: `config = load_config(Path("configs/x.yaml"), overrides=["a.b=3e-5"], registry=registry)`; the Orchestrator can use `add_config_arguments(parser)` (adds `--config PATH` and repeatable `--set A.B=VALUE`) and `load_config_from_args(args)`. Precedence: defaults in code < YAML (`extends: other.yaml` allowed) < environment `STT__SECTION__KEY` (also read from `.env`; the real environment wins) < `--set`. Offline by default: unless `runtime.online` is true, `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE` and `HF_DATASETS_OFFLINE` are set to 1. Use `config.section("name", SchemaClass)` to read a component's section.
- Inputs and outputs: a YAML path (optional), `--set` strings, environment, `.env` -> a frozen `AppConfig` (`runtime` plus the registered sections). `dump_config(config)` returns the resolved YAML text. Errors raise `ConfigError` (exit code 2) naming the key and how to fix it; all problems are reported together.
- How a component adds its section (no change to the loader): subclass `SectionModel` (frozen, unknown keys forbidden), then the composition root builds `SectionRegistry({"data": DataSection})` and passes it to `load_config`. `stt.config.validators` offers `ExistingPath` and `check_ratios_sum_to_one` for such schemas.
- Known limits: only the `runtime` section exists until components are built, so any other top-level key in a YAML file fails as unknown. `.env` lines are read only for `STT__` names (nothing else is exported). The dump has no comments (the per-key reference comes from `config-docs`, a later task). `extends` takes one file name, not a list.
- Tests: `tests/test_config.py` (34 tests, offline), `tests/test_package_layout.py`. Files: `src/stt/config/` (`schema.py`, `sources.py`, `loader.py`, `validators.py`, `errors.py`), `configs/base.yaml`, `.env.example`.
- Config keys (defined here):
  - `runtime.online` (bool, default false), `runtime.seed` (int, DEFAULT 42), `runtime.device` (`cpu` | `cuda` | `auto`, DEFAULT `cpu`; DECISIONS 87: `cuda` without a usable GPU is a ConfigError, exit code 2, never a silent fall back; resolved by `stt.config.device.resolve_device`).
    (Consistency fix after the full design review: the earlier draft keys `num_proc`, `dataloader_num_workers`, `runs_dir` and `log_level` are replaced by the section keys `features.num_workers`, `train.cpu_threads`, `run.experiments_dir` and `run.log.*`, so that no setting has two homes.)
  - Other sections are defined by the component that uses them.
  - Environment variable mapping: `STT__SECTION__KEY` overrides `section.key` (double underscore; decided in DECISIONS, section 2, item 31).

## C1 DataSource
- Status: built (wave 1); run once on the real Daf Yomi data (8723 rows, 0 rejected)
- Purpose: Load raw labeled audio + text from a LOCAL folder into one uniform list of `AudioSample`, and report what was loaded and what was rejected.
- How to use (project root, PowerShell, `$env:PYTHONPATH = "src"`; needs `data/daf_yomi_raw` from `tools/fetch_data.py`; the first run extracts about 800 MB of audio to `data/extracted/daf_yomi`, about 3 minutes; later runs reuse it, about 10 seconds):
  ```
  python -c "from pathlib import Path; from stt.config import SectionRegistry, load_config; from stt.datasource import DataConfig, create_data_source; c = load_config(Path('configs/data_gmara.yaml'), registry=SectionRegistry({'data': DataConfig})); r = create_data_source(c.section('data', DataConfig), Path('data/load_out')).load(); print(r.report.summary())"
  ```
  Output starts with `seen 8723, loaded 8723, rejected 0`, then the reasons, the counts per split, the number of groups and the duration summary. `rejected.csv` (id, reason, detail) is written to the folder given as `out_dir` (here `data/load_out`; in a run the RunManager passes the experiment folder). Config: copy `configs/data_gmara.yaml` and change the paths and column names.
- Inputs and outputs: config section `data` (class `DataConfig`, registered by the composition root with `SectionRegistry({"data": DataConfig})`) -> `LoadResult(samples sorted by id, report, rejections)`. `AudioSample`: `id`, `audio_path`, `text` (raw), `group_id`, `duration_sec` (from the audio header), `source_split`, `extra` (all other columns, typed by `data.extra_types`; nested `metadata` fields as `meta_<name>`). `LoadReport` has counts, rejection reasons, per-split counts, duration and numeric-extra distributions, empty values left out of `extra`, and how many `group_id` occur in more than one `source_split` (information only). Errors: `DataSourceError` (exit code 3).
- Sources (selected by `data.source.type` through `DataSourceRegistry`, `default_registry()`): `csv` = a folder with `manifest.csv` (UTF-8, BOM tolerated; relative audio paths are relative to the manifest); `hf_parquet` = a folder of parquet files, extracted to `data.extract.dir` (`audio/<split>/<id>.<ext>`, `manifest.csv` written last, `extract_info.json`), then read by the csv code. Parquet ids are `<split>_<row:06d>` (`<split>` = file name before the first `-`).
- Rejection reasons: `missing_audio`, `empty_text`, `unreadable_audio` (from the brief); `missing_group`, `malformed_row`, `bad_extra_value` (added, see DECISIONS 32). Failures: duplicate or empty id, a mapped column that does not exist (the existing columns are listed), no group column with `group_fallback: fail`, rejected ratio above `data.max_rejected_ratio` (after writing `rejected.csv`), zero samples, no parquet files, a reused extraction made from other source files.
- Known limits: audio arrays are never loaded (headers only). An empty value of a non-text `extra` type is left out of `extra` and counted (not a rejection). Extraction needs free disk space about the size of the parquet files. The duration is read from the header with soundfile, about 20 ms per mp3 file.
- Tests: `tests/test_datasource.py` (35 tests: the 10 acceptance tests of the brief plus edge cases; tiny synthetic wav and parquet files, offline).
- Config keys (planned):
  - `data.source.type` (`csv` | `hf_parquet`), `data.source.path` (folder)
  - `data.columns.id` (optional), `data.columns.audio`, `data.columns.text`, `data.columns.group`, `data.columns.split` (optional)
  - `data.group_fallback` (`parent_dir` | `file_stem` | `fail`) [DEFAULT: `fail`]: what to do when there is no group column. `fail` because a wrong group causes train/test leakage.
  - `data.extra_types` (mapping column -> `str|int|float|bool`)
  - `data.extract.dir`, `data.extract.overwrite` [DEFAULT: false]
  - `data.on_invalid` (`skip` | `fail`) [DEFAULT: `skip`]
  - `data.max_rejected_ratio` [DEFAULT: 0.05]: if more than this fraction is rejected, the run FAILS (safety gate against a wrongly configured mapping). The value is a starting point to be reviewed after the first real report.
  - Defaults for the Gmara dataset (example only, in the example YAML, not in code): audio=`audio`, text=`transcript`, group=`meta_entry_id`, split=`source_split` from the parquet file/split name.

## C3 Splitter
- Status: built (wave 1); run once on the real Daf Yomi data (8723 samples, 710 groups)
- Purpose: Divide the samples into named splits (default `train`, `val`, `test`) BY GROUP, deterministically, guaranteeing that no group appears in more than one split.
- How to use (project root, PowerShell, `$env:PYTHONPATH = "src"`; needs the extracted audio of C1):
  ```
  python -c "from pathlib import Path; from stt.config import SectionRegistry, load_config; from stt.datasource import DataConfig, create_data_source; from stt.splitter import SplitConfig, resolve_split; c = load_config(Path('configs/data_gmara.yaml'), overrides=['split.speaker_column=meta_creator'], registry=SectionRegistry({'data': DataConfig, 'split': SplitConfig})); s = create_data_source(c.section('data', DataConfig), Path('data/load_out')).load().samples; print(resolve_split(c.section('split', SplitConfig), c.runtime.seed, s).report.summary())"
  ```
  Output (about 15 seconds): `mode grouped_ratio, seed 42 ...`, `samples 8723, groups 710`, then `train: 6973 samples, 566 groups, 57.90 h, ratio 0.800`, the same for `val` and `test`, the largest groups, the overlap check, a table `source_split -> split`, and the speaker line. In code: `resolve_split(split_config, runtime_seed, samples)` returns a `SplitResult`; `default_registry().create(config, seed).split(samples)` splits without saving. Saving: set `split.dir` (the split is written to `<dir>/<version>/split.json` and reused by later runs; a new split needs a new `split.version`; `split.export_csv: true` also writes `split.csv`). Example YAML with every key and its DEFAULT: `configs/split_default.yaml`. In a command-line list, write JSON text, for example `--set 'split.names=["a","b"]'`.
- Inputs and outputs: `list[AudioSample]` (C1) -> `SplitResult`: `splits` (name -> samples sorted by id), `dropped_guard` (time_block only), `dropped_overlap` (predefined with `drop_from_train` only), `report` (`SplitReport`: per split samples, groups, hours, actual and requested ratio; the largest groups; the overlap check; the table source split -> split; a speaker line; both fingerprints), `fingerprint` (this split) and `data_fingerprint` (the input). Errors: `SplitError` (exit code 3).
- Modes (`split.mode`, a registry): `grouped_ratio` (DEFAULT: seeded stable order, each whole group goes to the split furthest below its target; fails when a ratio is missed by more than `split.ratio_tolerance`), `hash_group` (sha256 of seed and group: adding groups never moves old ones), `predefined` (uses `source_split`; missing names such as `val` are carved from the first split by group), `time_block` (cuts each recording into contiguous blocks by `meta_seek` with a guard gap; groups span splits by design). Hard checks after every split: no group in two splits (not for time_block), the union equals the input, no duplicate ids, no empty split; then the minimum gates and the oversized-group gate.
- Known limits: the official `eval` split is NOT used for the Test (decision 26): `source_split` is only reported. The Test measures new lessons, not new speakers; set `split.speaker_column` to see it in the report. No stratification and no text-duplicate check between splits (O19). With `hash_group` and few groups the shares can be uneven (the minimum gates fail instead). A saved split cannot be loaded after the data changed (fingerprint check): use a new `split.version` (with `hash_group` the old groups keep their splits). Neighbouring lessons of the same tractate can still share content (O18).
- Tests: `tests/test_splitter.py` (41 tests: the 10 acceptance tests of the brief plus edge cases; synthetic samples, no files, offline).
- Config keys (defined here, section `split`; `split.predefined.source_map` and `split.speaker_column` were added, see DECISIONS 33):
  - `split.mode` (`predefined` | `grouped_ratio` | `hash_group` | `time_block`) [DEFAULT: `grouped_ratio`; final choice OPEN, depends on the data check]
  - `split.group_key.column` [DEFAULT: the DataSource group column, i.e. one lesson/recording], `split.group_key.regex` [DEFAULT: none]
    - OPEN (O18): a content-level key, for example the tractate code extracted by regex from the `meta_source` column. Decided after the data is inspected.
  - `split.names` [DEFAULT: `train`, `val`, `test`]
  - `split.ratios` [DEFAULT: 0.8 / 0.1 / 0.1], `split.ratio_unit` (`duration` | `samples`) [DEFAULT: `duration`], `split.ratio_tolerance` [DEFAULT: 0.05 absolute]
  - `split.seed` (falls back to `runtime.seed`)
  - `split.min_samples_per_split` [DEFAULT: 30], `split.min_groups_per_split` [DEFAULT: 2]; both to be reviewed once the data volume is known (O22)
  - `split.on_oversized_group` (`fail` | `warn`) [DEFAULT: `fail`]
  - `split.on_overlap` (`fail` | `drop_from_train`) for `predefined` [DEFAULT: `fail`]
  - `split.time_block.order_column` [DEFAULT: `meta_seek`], `split.time_block.guard_gap_sec` [DEFAULT: 30]
  - `split.dir`, `split.version`, `split.reuse` [DEFAULT: true], `split.export_csv` [DEFAULT: false]

## C2 TextNormalizer
- Status: built (wave 1); run once on the 8723 real labels
- Purpose: Produce for every sample a training label text and an evaluation reference text from the raw transcript, by applying configurable, ordered normalization steps, and report what was found in the text.
- How to use (project root, PowerShell, `$env:PYTHONPATH = "src"; $env:PYTHONIOENCODING = "utf-8"`; needs the extracted audio of C1; about 20 seconds):
  ```
  python -c "from pathlib import Path; from stt.config import SectionRegistry, load_config; from stt.datasource import DataConfig, create_data_source; from stt.textnormalizer import TextConfig, TextNormalizer; c = load_config(Path('configs/data_gmara.yaml'), registry=SectionRegistry({'data': DataConfig, 'text': TextConfig})); s = create_data_source(c.section('data', DataConfig), Path('data/load_out')).load().samples; r = TextNormalizer(c.section('text', TextConfig)).normalize(s); print(r.report.summary()); print(r.samples[0].train_text); print(r.samples[0].eval_text)"
  ```
  Output: `samples 8723, eval_version 1`, the two step lists, the flag counts, and the character inventory (code point, Unicode name, counts in the raw text and in each profile), then the first label as `train_text` and as `eval_text`. For a plain string (the Evaluator does this for references and for model outputs): `from stt.textnormalizer import TextConfig, build_profile; f = build_profile(config.section("text", TextConfig), "eval"); f("<|0.5|>שלום, עולם. <|2.0|>")` gives `שלום עולם`. Example YAML with every key and its DEFAULT: `configs/text_default.yaml`. To see more than 50 characters in the inventory set `text.inventory.top_n`.
- Inputs and outputs: `list[AudioSample]` (C1) -> `NormalizeResult(samples, report)`. `NormalizedSample`: `sample` (unchanged, raw text stays in `sample.text`), `train_text`, `eval_text`, `timestamp_segments` (parsed before stripping; None when there are no tokens or they are malformed), `flags`. Flags: `had_timestamps`, `bad_timestamps`, `had_brackets`, `had_digits`, `had_latin`, `had_nikud`, `empty_after_normalization` (computed on the text with the timestamp tokens masked). `NormalizeReport`: flag counts, texts changed per profile, ids that became empty, the character inventory (every character that is not a Hebrew letter, a digit or whitespace; raw counts ignore the timestamp tokens), the eval version and the step lists. Samples are never dropped and keep the input order. Errors: `TextNormalizerError` (exit code 2) for an unknown step or profile (the registered names are listed); `text.train.timestamps: keep` fails at Config validation.
- Steps (registry, selected by name from the profile lists): `unicode_clean`, `strip_timestamps`, `remove_punctuation`, `unify_quotes`, `remove_nikud`, `remove_bracket_markup` (`chars_only`, `with_content`, `keep`), `lowercase_latin`, `collapse_whitespace`. A new step is a new class plus one line in `registry.py`. The profile applies its steps until the text stops changing (so it is idempotent even when removing characters creates a new pattern).
- Known limits: v1 strips timestamps only (no `keep`). No spelling correction, abbreviation expansion or number normalization. No text-duplicate check between splits (O19: figures were measured once, see OPEN_ISSUES). In `eval_text` the geresh is removed, so `גמ׳` becomes `גמ` and `ה׳` becomes `ה` (owner decision 29). The default punctuation list also removes hyphens and dashes (replaced by nothing, except the maqaf which becomes a space); none occurs in the Daf Yomi data. Changing the eval profile needs a new `text.eval_version`.
- Tests: `tests/test_textnormalizer.py` (36 tests: the 11 acceptance tests of the brief, a random idempotence test, offline).
- Config keys (section `text`; `text.punctuation.space_chars`, `text.unicode.invisible_chars` and `text.timestamp_pattern` were added, see DECISIONS 34):
  - `text.eval_version` [DEFAULT: 1]
  - `text.profiles.train.steps` [DEFAULT: `unicode_clean`, `strip_timestamps`, `unify_quotes`, `remove_bracket_markup`, `collapse_whitespace`]
  - `text.profiles.eval.steps` [DEFAULT: `unicode_clean`, `strip_timestamps`, `remove_punctuation`, `unify_quotes`, `remove_nikud`, `remove_bracket_markup`, `lowercase_latin`, `collapse_whitespace`]
  - `text.train.timestamps` (`strip` in v1; `keep` reserved for a later extension) [DEFAULT: `strip`]
  - `text.bracket.pairs` [DEFAULT: `[` `]` and `(` `)`], `text.bracket.mode` [DEFAULT: `chars_only`]; optional per-profile override `text.profiles.<name>.bracket_mode` [DEFAULT: unset = use `text.bracket.mode`]. Recipe for a non-speech marker (O47): train profile `keep`, eval profile `with_content`, so the marker is learned but never counted in the WER. Defaults are unchanged, so nothing happens unless the config asks for it.
  - `text.punctuation.chars` [DEFAULT: a standard Hebrew and Latin punctuation set, listed in the example YAML]
  - `text.quotes.map` [DEFAULT: ׳ ' ’ unified to one form; ״ " “ ” unified to one form]
  - `text.inventory.top_n` [DEFAULT: 50]

## C1b SampleFilter
- Status: built (wave 1); run once on the real data in report mode
- Purpose: Decide, per split, which `AudioSample`s are kept according to configurable rules, and report exactly what was removed and why.
- How to use (project root, PowerShell, `$env:PYTHONPATH = "src"`; needs the extracted audio of C1; about 25 seconds):
  ```
  python -c "from pathlib import Path; from stt.config import SectionRegistry, load_config; from stt.datasource import DataConfig, create_data_source; from stt.splitter import SplitConfig, resolve_split; from stt.textnormalizer import TextConfig, TextNormalizer; from stt.samplefilter import FilterConfig, SampleFilter; c = load_config(Path('configs/data_gmara.yaml'), registry=SectionRegistry({'data': DataConfig, 'split': SplitConfig, 'text': TextConfig, 'filter': FilterConfig})); s = create_data_source(c.section('data', DataConfig), Path('data/load_out')).load().samples; sp = resolve_split(c.section('split', SplitConfig), c.runtime.seed, s); n = {x.sample.id: x for x in TextNormalizer(c.section('text', TextConfig)).normalize(s).samples}; f = SampleFilter(c.section('filter', FilterConfig)); [print(r.report.summary()) for r in f.filter_splits({k: [n[x.id] for x in v] for k, v in sp.splits.items()}).values()]"
  ```
  Output: for each split `split train: mode report, seen 6973, kept 6973, would reject 0, would-be kept ratio 1.0000` and one line per running rule with its threshold and failure count. Change a threshold with `--set`-style overrides, for example `overrides=["filter.rules.min_duration.threshold=5"]` in `load_config`, or in YAML (`configs/filter_default.yaml`). In code: `SampleFilter(filter_config, token_counter=None).filter(normalized_samples, "train")` returns a `FilterResult`; `filter_splits({"train": [...], "test": [...]})` does every split.
- Inputs and outputs: `NormalizedSample`s of one split (C2) plus the split name -> `FilterResult(kept, rejected, would_reject, report)`. `kept` keeps the input order; in `report` mode (DEFAULT) `kept` is everything and `rejected` is empty, `would_reject` always lists the samples that fail a rule (id, failed rule names, reasons); in `apply` mode `rejected` equals `would_reject`. `FilterReport`: counts, would-be kept ratio, one line per rule run (kind, threshold, failures), the rules not applied to this split. Errors: `FilterError` (exit code 3) for an unknown rule name (the registered names are listed), an enabled rule without threshold or field or token counter, or a field missing from the samples (rule and field named; fix: map the column or set the rule `enabled: false`); `FilterGateError` (a `FilterError`) when a split would keep less than `filter.min_kept_ratio` (per-rule breakdown; the error carries the full `result`) or is empty after `apply`.
- Rules (registry, defaults): structural, all splits: `min_duration` 1.0 s, `max_duration` 30.0 s, `min_text_chars` 2 on `eval_text` (`measure_on` can be `train_text`); quality, train only, OFF until a threshold is set: `min_quality_score`, `max_bad_segments` (both need `field`, the name of the sample field they read), `require_golden` (needs `enabled: true` and `field`); optional structural `max_label_tokens` (OFF; measures `train_text` with a token counter injected as `Callable[[str], int]`; this is the alternative of open issue O34, the brief keeps label-length removal in the FeaturePipeline). A rule you do not mention in YAML keeps its default; setting a threshold on a disabled rule enables it. A new rule is a new class plus one `RuleSpec` in a registry; the filter is not edited.
- Known limits: thresholds are DEFAULT and permissive (they remove nothing from the Daf Yomi data); the final values are decided from the report and an A/B experiment (O5, O6). The gate checks the would-be kept ratio in both modes. The filter imports no tokenizer. No text-length-to-duration rule (O13, a later class). Rules never read audio: the duration is `AudioSample.duration_sec` from the C1 header.
- Tests: `tests/test_samplefilter.py` (29 tests: the 8 acceptance tests of the brief plus config, defaults and the token rule with a fake counter; offline).
- Config keys (section `filter`; the rule keys are `enabled`, `applies_to`, `kind`, `threshold`, `field`, `measure_on`, see DECISIONS 35):
  - `filter.mode` (`report` | `apply`) [DEFAULT: `report`]
  - `filter.rules.<rule_name>.enabled`, `.applies_to` (list of splits), `.kind` (`structural` | `quality`), plus the rule's threshold:
    - `min_duration` [DEFAULT: 1.0 s], `max_duration` [DEFAULT: 30.0 s, the Whisper window; changed from 30.5 after the FeaturePipeline discussion: the filter removes longer clips, FeaturePipeline never truncates and FAILS if a longer clip arrives. Apply mode is required for this to take effect]
    - `min_text_chars` [DEFAULT: 2], measured on `eval_text` (after normalization, so timestamp tokens and punctuation do not count); optional key `measure_on` (`eval_text` | `train_text`) [DEFAULT: `eval_text`]. For clips labeled with a non-speech marker (O47) the recipe is `measure_on: train_text` for the train split, so they are not removed as "empty"; their empty reference is excluded from the WER by the Evaluator
    - `min_quality_score` [DEFAULT: null = disabled], `max_bad_segments` [DEFAULT: null = disabled], `require_golden` [DEFAULT: false]
    - defaults are deliberately permissive (reject only obviously broken samples) until the first real report is reviewed.
  - `filter.min_kept_ratio` [DEFAULT: 0.4]: if a split keeps less than this fraction, the run FAILS (safety gate).

## C3b Subsampler
- Status: built (wave 2); run once on the real Daf Yomi splits (sizes, nesting, fixed Val and Test, determinism); wired into the `prepare` stage, OFF by default
- Purpose: Select, deterministically and reproducibly, a smaller subset of the samples to the size requested in Config, and report exactly what was selected.
- How to use (project root, PowerShell, `$env:PYTHONPATH = "src"`; needs the data of C1; about 15 seconds; the experiment goes to a temporary folder that you can delete):
  ```
  python -m stt prepare --config configs/data_gmara.yaml --set model.path=models/whisper-tiny --set run.experiments_dir=data/c3b_example --set subsample.enabled=true --set subsample.preset=tiny
  Get-Content data/c3b_example/exp_0001/reports/subsample_report.txt
  Remove-Item -Recurse -Force data/c3b_example
  ```
  Output: the JSON summary with `kept_train 61, kept_val 875, kept_test 875`, then the report: `requested 30 minutes ... achieved 30.34 minutes ... overshoot +0.34 minutes`, and the sizes before and after of Train (reduced), Val and Test (untouched). In code: `resolve_subsample(subsample_config, runtime_seed, splits, "train", "val")` with `splits` = `{name: [NormalizedSample]}` after the filter, or `Subsampler().subsample(splits, spec)` with a `SubsampleSpec`. In a run the section is `subsample` (class `SubsampleConfig`); example YAML: `configs/subsample_default.yaml`. Sizes on the command line: `--set 'subsample.size={"minutes": 30}'` (JSON text), or `--set subsample.preset=tiny`.
- Inputs and outputs: `Subsampler.subsample(splits, spec) -> SubsampleResult(splits, report, fingerprint)`. `SubsampleSpec`: `size` (`all`, `minutes`, `samples` or `fraction`), `strategy`, `scope`, `val`, `seed`, `repeat_index`, plus `train_split`, `val_split`, `min_train_samples`. `splits` keep the input order inside each split. `SubsampleReport`: requested size, per split before and after (samples, groups, minutes) and whether it was reduced, achieved size and the overshoot of Train, warnings (a single group in Train), where the ids are stored. `SubsampleStore` writes and reads the JSON (`<size>_<strategy>_<scope>_<val>_s<seed>_r<repeat>.json`: the spec, the fingerprints and the ids). Errors: `SubsampleConfigError` (exit code 2: unknown strategy, scope or preset, a minutes or samples size with scope all_splits, `val: follow` without a Val split) and `SubsampleError` (exit code 3: a size larger than what exists with both numbers, fewer than `min_train_samples`, a split that would be empty, a stale or damaged stored file).
- Rules kept: every unit (a sample or a whole group) gets a rank from the SHA-256 of `seed|repeat_index|unit key` and units are taken in rank order until the size is reached, so the same inputs give the same subset, the input order does not matter and a smaller subset is inside a larger one; the unit that crosses the target is included (overshoot at most one unit, reported); `by_group` never splits a group; `train_only` leaves Val and Test as the same objects in the same order; `val: follow` reduces Val by the same share as Train; `val_samples: N` keeps a FIXED Val slice of N samples whatever the Train size (the same slice for every Train size, nested, Train_only scope, not with `follow`; owner decision O78); `all_splits` reduces all three by the same fraction (a fraction or `all` is required); a `fraction` is a share of the MINUTES of audio; a size larger than available FAILS (unless `all`); no sample is modified and no file is touched except through the store (a stored file is never overwritten and never reused when the spec or the data changed); `enabled: false` returns the input unchanged. No stratification.
- Presets (built in; `subsample.preset`): `smoke` 20 samples, `tiny` 30 minutes, `work_like` 10% of the audio by group over ALL splits, `half` 50% of the audio, `full` all. A preset replaces the size and, where it defines them, the strategy and the scope. With a frozen encoder (`train.freeze_policy: freeze_encoder`, passed in by the wiring) the output of the encoder is computed once per clip into `enc_<hash>_<dtype>/` (atomic, resumable, with progress and a disk check), a one-time self-check compares the Val loss with and without it on 3 clips, and the examples carry `encoder_output`; the collator returns `encoder_outputs` and the Evaluator and the Trainer skip the encoder. Refusals (exit code 2): policy not `freeze_encoder`, dropout or layerdrop above 0, `apply_spec_augment`, not enough disk. Files: `encoder_cache.py`, `encoder_adapter.py` (torch). Tests: `tests/test_encoder_cache.py` (19). Measured on the turbo model (8 clips): training step 60 s to 7.5 s, Val loss pass 120 s to 5 s, decoding 130 s to 24 s, identical results.

## C8 HyperparamSearcher
- Status: built (wave 2); NOT wired into the Orchestrator yet (the `search` stage is a separate later task); checked with a fake trial runner and once with a real two-trial search on the tiny test model through the TrainerCore
- Purpose: Propose hyperparameter sets, hand each one to a trial runner, record every outcome, and return the ranked candidates within a budget.
- How to use (project root, PowerShell, `$env:PYTHONPATH = "src"`; a synthetic objective, no training, under a second):
  ```
  python -c "import sys; sys.path.insert(0, 'tests'); from search_fakes import BowlRunner; from stt.searcher import HyperparamSearcher, SearchConfig, build_spec; r = HyperparamSearcher().search(build_spec(SearchConfig.model_validate({'strategy': 'grid'}), 42, 4), BowlRunner()); print(r.report.summary())"
  ```
  Output: `search (grid, seed 42): 6 trials (6 complete, 0 pruned, 0 failed; 0 from an earlier run)`, the best Val loss with its parameters, the time and the threads per trial, and the notes. In code: `result = HyperparamSearcher().search(build_spec(search_config, runtime_seed, total_threads), run_trial)`; `run_trial(trial, report)` is the `TrialRunner` the Orchestrator builds (it trains with `apply_params(base_hyperparams, trial.params)` and passes `report` as the `on_eval` callback of the TrainerCore). In a run the section is `search` (class `SearchConfig`); example YAML: `configs/search_default.yaml`.
- Inputs and outputs: `SearchSpec` (parameters as `ParamRange`, strategy, `n_trials`, `time_budget_minutes`, pruning, `parallel_trials`, failure limits, `finalists_k`, `study_dir`, seed, `total_threads`) and a `TrialRunner` -> `SearchResult(trials, ranked, stopped_reason, report)`: `trials` is every `TrialRecord` (the `Trial` with its parameters and thread limit, and the `TrialOutcome`: status `complete` | `pruned` | `failed`, Val loss, steps, seconds, model folder, error, the Val losses it reported), `ranked` the completed trials by Val loss (best first, at most `finalists_k`), `stopped_reason` is `n_trials` | `time_budget` | `too_many_failures` | `space_exhausted`. The `report` has the counts, the best parameters, the time, the parallel setting and honest notes (the sequence can vary with pruning or parallel trials; a resumed search does not repeat an uninterrupted one; the best trial is at the edge of a range). Errors: `SearchConfigError` (exit code 2: unknown strategy, Optuna missing with the advice `grid`, `parallel_trials` above the cores with both numbers, a stored study with another space, strategy or seed with both named) and `SearchError` (exit code 4: no trial completed, with the failure reasons or the advice to relax pruning, carrying the result so far; or the study file cannot be written). `SearchInterrupted` is raised BY a runner when the user asked to stop; the searcher keeps the finished trials and raises it again.
- Strategies (registry): `grid` (own code, no dependency: the product of the values of each parameter in a fixed order; `log_float` geometric, `float` even, `int` every whole number, `categorical` as listed; `points` values per range) and `optuna_tpe` (the TPE sampler of Optuna by ask and tell with an in-memory study and a seed; `optuna_strategy.py` is the ONLY module that imports Optuna, and only when this strategy is chosen). Pruning is the searcher's own MEDIAN RULE for both: after `pruning.min_evals` Val evaluations a trial is stopped when its Val loss is worse than the median of the other finished trials at the same evaluation (at least two such trials must exist, so the first trials are never pruned). The rule fires only for trials that evaluate four times or more.
- The study: `study.json` in `search/` of the experiment: the space (parameters, strategy, seed), and every finished trial, rewritten after each trial. A rerun with the same space continues (the counts add up: `n_trials` counts the earlier trials too, a larger budget runs the rest); a changed space, strategy or seed FAILS naming both. The grid skips the combinations already tried; `optuna_tpe` replays the stored trials into its in-memory study (so no Optuna storage, database or file locking is involved).
- Parallel trials (`search.parallel_trials` above 1): each trial runs in its own worker process (`spawn`, the only start method on Windows) with `total_threads // parallel_trials` threads (`Trial.threads`); the PARENT process owns the strategy, the pruning and the study file, and the workers talk to it through a pipe, so no file is shared between processes. The runner must be picklable. A worker that dies is recorded as a failed trial. Tested with real worker processes.
- Known limits: the searcher does not train or evaluate and does not declare a winner. The objective is the Val loss of the trial; with few evaluations per trial pruning rarely fires. A search at the screening size is not cheap on this CPU (see the budget table in DECISIONS 49): measured per example 1.24 s for training and 0.415 s for the Val loss with whisper-tiny at 2 threads. The Val set used by the trials should be a SLICE: `subsample.val_samples` (for example 100, O78) gives a fixed one. `parallel_trials` is verified only with a fake runner; the speed-up on the real machine is not measured (the cores are shared with the machine's other work).
- What the `search` stage needed (BUILT in Orchestrator Part 1, see C13 and DECISIONS 55: items (1) to (4); item (5), the finalist retraining and the Selector steps, was built in Part 2): (1) a `TrialRunner` class made by the Orchestrator, picklable when `parallel_trials` is above 1 (it rebuilds its services from the config path in the worker): a fresh model, the screening split (the Subsampler preset `search.screening.preset` on Train, and a Val slice), the features, a `TrainRequest` with `apply_params(base, trial.params)`, `on_eval=report`, `stop_flag`, the thread limit `trial.threads`, the output folder `candidates/exp_NNNN_trial_TTT` and the model name prefix from the RunManager (`model_name_prefix`), the metrics folder `metrics/trial_TTT`; it returns `TrialOutcome(val_loss=best Val loss, steps, seconds, model_dir)` and raises `SearchInterrupted` when the stop flag stopped the training; (2) `SearchConfig.study_dir` = `handle.paths.search` and `build_spec(config, runtime_seed, resolve_threads(train_config))`; (3) a `search` stage in the stage registry (`depends_on` prepare; the config slice: search, train, model, features, subsample, data, split, text, filter) that writes `reports/search_report.txt` and the trials as JSON through the RunManager and puts the counts and the best parameters in its summary; (4) the exit codes in `wiring.exit_code_for` (`SearchConfigError` 2, `SearchError` 4) and `StageInterrupted` from `SearchInterrupted`; (5) the finalist retraining on the full data through a second runner (a full-data setting) and the Evaluator and Selector steps after it (Wave 2: C9).
- Tests: `tests/test_searcher.py` (28 tests: the 10 acceptance tests of the brief, the study, the config, the interrupt, the failure and pruning rules, the real worker processes; offline, about 3 seconds) with the fake runners in `tests/search_fakes.py`.
- Config keys (section `search`; NEW keys and a changed DEFAULT marked):
  - `search.strategy` [DEFAULT: `grid` (owner decision 2026-10-05, O79); `optuna_tpe` stays available, see the comparison in DECISIONS 49]
  - `search.parameters.<name>` with `kind`, `low`, `high`, `choices` and `points` [NEW key `points`, DEFAULT 3]; DEFAULT space: `learning_rate` (log range 5e-6 to 5e-5) and `grad_accum_steps` (2 or 4), nothing else (owner); naming `parameters` replaces the space; `max_steps` and `seed` cannot be searched
  - `search.n_trials` [DEFAULT: 6, thinned from the brief's 10 (needs your approval)], `search.time_budget_minutes` [DEFAULT: null]
  - `search.pruning.enabled` [DEFAULT: true], `search.pruning.min_evals` [DEFAULT: 3]
  - `search.parallel_trials` [DEFAULT: 1]
  - `search.max_failed_ratio` [DEFAULT: 0.5], `search.min_trials_before_abort` [DEFAULT: 4]

## C9 Selector
- Status: built (wave 2); NOT wired into the Orchestrator yet (the selection stage is a separate later task); run on the stored Val evaluation of `experiments/exp_0001` and on three readable scenarios of fake results (no Test evaluation)
- Purpose: Decide, from evaluated finalists and the baseline, which model is the winner, or declare that the baseline stays.
- How to use (project root, PowerShell, `$env:PYTHONPATH = "src"`; fake evaluation results made by the real Evaluator, no model weights used beyond the stored tiny test model; about 3 seconds):
  ```
  python -c "import sys; sys.path.insert(0, 'tests'); from selector_fakes import FakeTest, candidate, make_result; from stt.evaluator import Comparator, EvalConfig; from stt.selector import SelectConfig, SelectionRequest, Selector; r = Selector(SelectConfig()).select(SelectionRequest(make_result('val', 4), [candidate(0, 1), candidate(1, 3)], Comparator(EvalConfig(), 42), FakeTest({None: 4, 0: 2}))); print(r.verdict, r.test_status); print(r.reason)"
  ```
  Output: `winner confirmed`, then the plain-language reason: `Trial 0 (learning_rate 1e-05, grad_accum_steps 4) is the winner: its Val WER is 0.1000 against 0.4000 for the baseline ... The Test confirms it: ...`. In code: `result = Selector(select_config).select(SelectionRequest(baseline_val, candidates, comparator, evaluate_test, test_split))`; `candidates` are `Candidate`s (trial id, parameters, model folder, the Val `EvalResult`, Val loss, steps), `comparator` is the Evaluator's `Comparator`, `evaluate_test(candidate | None)` is the ONE-TIME Test evaluation (`None` = the baseline model) wrapped by the Orchestrator in a `TestOnceGuard`. In a run the section is `select` (class `SelectConfig`); example YAML: `configs/select_default.yaml`.
- Inputs and outputs: `SelectionResult`: `verdict` (`winner` | `baseline_retained`), `winner`, `ranking` (every finalist with its comparison, eligibility and the reason in words), `comparison_table` (all finalists side by side: rank, trial, parameters, Val WER, CER, difference from the baseline, interval, verdict, Val loss, steps, eligible, note; the winner first, then the other eligible by Val WER, then the others), `test_status` (`confirmed` | `not_confirmed` | `not_evaluated`), `test_comparison`, `test_baseline` and `test_winner` (the Test EvalResults), `test_error`, `review_list` (the winner's list, or the baseline's when it stays, passed through as the same object), `warnings`, and `reason` (plain sentences for a human). Errors: `SelectorError` (exit code 4: no candidates, duplicate trial ids, a candidate without a Val result, a Val result that carries the Test split name, another evaluation profile (`eval_version`), different file sets, a Test result that is not on the Test split) and `TestAlreadyEvaluatedError` (the Test requested twice for one model). `baseline_retained` is a RESULT, exit code 0, not an error.
- Rules kept: Val decides; a candidate is eligible when its Val comparison with the baseline reaches `select.min_verdict` (default `improved`, at the level of evidence of `eval.significance`); the lowest Val WER among the eligible wins, a difference below `select.tie_epsilon` (0.001) is a tie and the lower Val loss decides it (then the lower trial id: no randomness anywhere); no eligible candidate gives `baseline_retained`; the Test is evaluated ONCE for the winner and ONCE for the baseline and NEVER when the baseline stays or `select.test_confirmation` is false; a second Test call for one model fails, also after a failed first call (`TestOnceGuard`); a winner that the Test does not confirm (no clear difference or worse) stays the winner and is flagged `not_confirmed` with the Test numbers beside it; a failing Test evaluation keeps the winner, sets `not_evaluated` and reports the error; with too few groups for a confidence statement (`insufficient_groups`) the candidate is judged by the plain WER difference and flagged (`select.on_insufficient_groups`), or rejected; the Test callable is never used to pick among candidates; the Selector reads and writes no file, trains and evaluates nothing, and imports no model library.
- Known limits: ONE implementation. The Test confirmation counts only a verdict `improved` as confirmed (the same level as Val; a stricter level is open, O81). Finalists repeated with several seeds are not aggregated (later stage). The listening verdict of the owner is not used (O43). The Selector does not save the winner (ModelRegistry, C10) and does not write the report (RunManager and ReportBuilder). The EvalResults of the stages must be passed in memory; storing them between commands needs a codec (see below).
- What the selection stage needed (BUILT in Orchestrator Part 2, see C13 and DECISIONS 57): (1) after the search and the finalist retraining on the full data, every finalist evaluated on the Val split by the Evaluator, giving the `Candidate` list (trial id, parameters, model folder, Val `EvalResult`, Val loss, steps) and the baseline's Val `EvalResult` of the same experiment; (2) a ONE-TIME Test callable made by the Orchestrator and wrapped in ONE `TestOnceGuard` per experiment: it loads the model (`candidate.model_dir`, or the baseline model for `None`), builds the features of the configured Test split (`pipeline.test_split`), and evaluates with the same profile and settings; it must return a result whose `split_name` is the Test split; (3) the Comparator and `select` config from the config; (4) writing the results through the RunManager: `reports/selection.json`, the comparison table as CSV, the reason as text, and the flag `not_confirmed` in the summary; (5) the exit codes (`SelectorError` 4; the verdict `baseline_retained` is exit code 0); (6) a way to keep the Val `EvalResult`s between commands (the evaluate stage today stores only summaries, predictions and a review list; UPDATE Orchestrator Part 1: the lossless codec is built, `stt.evaluator.codec`; Part 2 makes the evaluate stage store the baseline result with it); (7) the hand-over to the ModelRegistry (C10) and the test-set usage counter (O59).
- Tests: `tests/test_selector.py` (17 tests: the 10 acceptance tests of the brief, the Test-once rules, the split-name guards, the failure cases, the config and the import rules; offline, about 10 seconds) with `tests/selector_fakes.py`.
- Config keys (section `select`; no key was added to the brief):
  - `select.min_verdict` [DEFAULT: `improved`; or `no_clear_difference`]
  - `select.tie_epsilon` [DEFAULT: 0.001 absolute WER]
  - `select.on_insufficient_groups` [DEFAULT: `plain_difference`; or `reject`]
  - `select.test_confirmation` [DEFAULT: true]

## C10 ModelRegistry
- Status: built (wave 2); NOT wired into the Orchestrator yet (the registration stage and the `registry` command are a separate later task); run once on a temporary registry with the retained-baseline result of `experiments/exp_0001` and a small fake winner (a few small files, not a real model), then deleted
- Purpose: Store the selected model together with its metadata as an immutable, numbered entry, and keep an index of all entries.
- How to use (project root, PowerShell, `$env:PYTHONPATH = "src"`; reads a registry folder, creates nothing; the registration itself is shown by the tests and by the stage that will call it):
  ```
  python -c "from stt.registry import ModelRegistry, RegistryConfig; r = ModelRegistry(RegistryConfig(dir='data/c10_example')); print(r.list_entries(), r.best(1, 'x'))"
  python -m unittest tests.test_registry -v
  ```
  Output of the first line: `[] None` (no entry yet). In code: `registry = ModelRegistry(registry_config)`; `entry = registry.register(RegisterRequest(selection, card, experiment_id, finalist_dirs, review_text))` with `card = card_from_selection(selection, baseline_val, base_model_name=..., base_model_path=..., data_fingerprint=..., split_fingerprint=..., subsample_fingerprint=..., config_ref=handle.config_ref, library_versions=..., seed=..., code_version=..., generated_at=...)`; then `registry.get("model_0001")`, `registry.list_entries()`, `registry.best(eval_version, test_fingerprint)`, `registry.verify("model_0001")`, `registry.rebuild_index()`, `registry.test_set_count(fingerprint)`. In a run the section is `registry` (class `RegistryConfig`); example YAML: `configs/registry_default.yaml`.
- THE REGISTRY FOLDER (one self-contained folder: copy it whole, for example to a removable drive): `registry/index.csv` (one row per entry; open it in Excel), `registry/model_0001/model/` (the winner's model folder: weights, tokenizer files and `pipeline_model_info.json`, absent for a retained baseline), `model_card.json` (the facts as data), `MODEL_CARD.md` (the same in plain English, to read), `review_list.txt` (the files to listen to, with the audio paths at the time of the run) and `SHA256SUMS` (one line per file of the entry, the format of `sha256sum -c`). Names are numbers, never dates (`model_0001`, `model_0002`, ...), each linked to its experiment (`exp_0001`) and to that experiment's `config_full.yaml` through the card (`config_ref`). The default folder is `registry/` next to the project, OUTSIDE the experiments folder, so no experiment cleanup can reach it, and it is covered by `.gitignore`.
- Inputs and outputs: `RegisterRequest(selection: SelectionResult, card: ModelCard, experiment_id, finalist_dirs, review_text)` -> `RegistryEntry(entry_id, experiment_id, kind (`model` | `baseline_retained`), model_dir, card_path, checksums_path, test_evaluations)`. `ModelCard`: the kind and verdict, the base model, the data, split, subsample and Test-set fingerprints, the config reference, `eval_version`, the Val and Test summaries (`EvalSummary`: WER, CER, mean per-file WER, files, words, the share of files under each threshold, the baseline WER, the difference, the interval, the confidence, the verdict, the number of groups), the Test status, the decode settings, the searched parameters, ALL finalists, the library versions, the seed, the code version, the time (passed in), the Selector's reason and the flags. `VerifyReport(files_checked, missing, mismatching, ok)`. Errors: `RegistryError` (exit code 4: the card does not match the selection, a missing or empty winner folder, a finalist folder that contains or lies inside the registry, a damaged or stale index, a leftover temporary folder, a copy that differs from the original) and `RegistryVerifyError` (exit code 5: `verify` found missing, changed or unlisted files, listed in the message; the report is attached).
- Rules kept: entries are numbered one above the highest existing (a gap stays a gap) and NEVER overwritten or edited; registration is crash-safe: the number is reserved by a temporary folder `.tmp_model_NNNN`, the model folder is moved (a verified copy across drives) into it, the card, the markdown, the review list and `SHA256SUMS` are written there, the folder is renamed into place, the checksums are verified in the final place, the index is updated, and only then the other finalists and the checkpoints named in the request are deleted; a failure at any step puts the model folder back where it was and removes the temporary folder, so the registry is unchanged and the cleanup does not run; with `registry.cleanup` false or `registry.keep_finalists` true nothing is deleted; a `baseline_retained` entry is recorded (card and index row, no model folder, flagged `test_not_evaluated`); the Test-set usage counter: every card and index row carries how many registered entries (this one included) were evaluated on the same Test set, and the markdown says 'this Test set has been looked at N time(s)' as a lower bound; `best` looks only at entries of kind `model` with the same `eval_version` and the same Test-set fingerprint and takes the lowest Val WER (ties: the lower entry number), and returns None when none matches; the index is derived from the cards: a missing, damaged or mismatching index FAILS with the fix `rebuild_index()` and is never rebuilt silently; the winner folder is MOVED (renamed on the same drive, a verified copy and a delete after success across drives) unless `registry.transfer` is `copy`; no network, no model loading, no evaluation, no torch or Hugging Face import; paths with spaces and Hebrew characters work.
- The fingerprint of a Test set (`test_set_fingerprint(eval_result)`): SHA-256 over the sorted lines `sample_id|group_id|first 16 hex characters of the SHA-256 of the reference text`. The same files with the same reference texts give the same fingerprint, whatever the model, the order or the decoding; another file list, group or reference text (another text profile) gives another one.
- Known limits: one machine at a time (no file locking between processes). - What the stages do: `prepare` loads, splits, normalizes and filters the data and writes `load_report.txt`, `split_report.txt`, `text_report.txt`, `filter_report.txt` and `rejected.csv` into `reports/`. `train` runs one trial: the output folder is `candidates/exp_NNNN_trial_TTT/`, the live metrics are `metrics/trial_TTT/metrics.csv`, the model folder is named `exp_NNNN_trial_TTT_step_SSSSS` and loads through the ModelLoader (`source_config_ref` = `exp_NNNN/config_full.yaml`); a trial folder with a complete checkpoint is RESUMED, otherwise a new trial number is used (nothing is overwritten). `evaluate` scores the baseline model on the Val split and, if the experiment has a trained model, the trained model too, compares them and writes `evaluation_<baseline|trained>.json`, `predictions_<...>.csv` (one row per file), `review_<...>.txt` (the human review list) and `comparison.json` (a stop-gap until the ReportBuilder). The Orchestrator builds the per-file attributes for the Evaluator: `duration`, `ref_words`, `label_tokens`, numeric `extra` fields (`extra_<name>`) and text flags (`flag_<name>`). Every finished stage writes a completion marker (with a fingerprint of its config slice and of the stages it depends on) into `status.json` and its result into `reports/stage_results/<stage>.json`.
- The `search` stage and command (Wave 2, Orchestrator Part 1; DECISIONS 55): `python -m stt search --config my.yaml` = prepare + the hyperparameter search of C8 on a SCREENING subset: the Subsampler preset `search.screening.preset` (default `tiny`) is applied to the prepared Train data, and `subsample.val_samples` is the fixed Val slice (SET IT for real runs: without it every Val evaluation of every trial scores the whole Val set). The trials run one after another (`search.parallel_trials: 1`) or in worker processes (`parallel_trials: 2` = two trials at once, each with `train.cpu_threads` divided by 2 threads). Each trial loads a fresh model, trains with `apply_params(train.hyperparams, the trial's values)` (everything in `train.hyperparams` stays fixed except the searched keys, by default `learning_rate` and `grad_accum_steps`), reports every Val loss to the searcher (pruning and the time budget answer through it) and keeps its files in `candidates/exp_NNNN_trial_TTT/` (the model folder is `exp_NNNN_trial_TTT_step_SSSSS`) and `metrics/trial_TTT/` (TTT is the searcher's trial number, from 000). Files of the stage: `search/study.json` (written after every finished trial), `search/trial_TTT.params.json` (the parameters an in-flight trial folder was started with), `reports/search_report.txt` (the trials in a table, the finalists, the notes; READ THIS FIRST), `reports/search_trials.json` (the same as data), `reports/search_screening.txt` (the Subsampler report) and, for the worker processes, `logs/trial_TTT.log`. The summary has the counts, the stop reason, the best Val loss and parameters and the finalist trial numbers (`finalist_trials`, the best `search.finalists.k` by Val loss). RESUME: Ctrl+C (or Ctrl+Break) stops the running trial(s) after the current step with a checkpoint (exit code 130); the same command with `--experiment exp_NNNN` keeps the finished trials and continues (an interrupted trial of a sequential search continues from its checkpoint when its parameters are the same; a folder that cannot be resumed is renamed `..._stale_N`, never deleted); a larger `search.n_trials` continues the same study; another search space, strategy or seed than the stored study is refused (exit code 2). Exit codes: 2 for a wrong search setting (unknown strategy or parameter, `parallel_trials` above the cores, another space than the stored study), 4 when no trial completed (the reports are still written), 130 stopped. It does NOT retrain the finalists, select or register (Part 2), and the Test split is never built or scored. The `prepare` summary now also holds `data_fingerprint`, `split_fingerprint` and (only when the Subsampler is on) `subsample_fingerprint` for the model card. The disk use of the trial folders grows with the model size (O86).
- The Part 2 stages and the `run` command (Wave 2, Orchestrator Part 2; DECISIONS 57): `python -m stt run --config my.yaml` runs the stages of `pipeline.stages` (DEFAULT `prepare`, `evaluate`, `search`, `finalists`, `select_and_register`); a rerun with `--experiment exp_NNNN` skips the finished stages and continues (an interrupted finalist is resumed); at the end the console says the VERDICT in plain words (`winner` or `baseline_retained`, the reason, the Test status and the registry entry). `evaluate` here is the baseline on the Val split: it now also stores the lossless result `reports/eval_result_baseline.json` (the codec of C7), which the selection reads. `finalists` reads the best `search.finalists.k` trials from `reports/search_trials.json` and for each one trains a fresh model with the trial's hyperparameters on the FULL Train split of the prepared data, with the screening Val slice (`subsample.val_samples`) as the Val loss that picks the best checkpoint, then scores it by WER on the FULL evaluation split (Val); files: `candidates/exp_NNNN_final_trial_TTT/` (model folder `..._step_SSSSS`), `metrics/final_trial_TTT/`, `reports/finalists/final_trial_TTT.json` and `.val.json` (the lossless Val result), `predictions_...csv`, `review_...txt`, and `reports/finalists_report.txt`; a finished finalist is not trained again, an interrupted one resumes (same rules as the search trials); `search.finalist_repeats` above 1 is refused with exit code 2 (O90). `select_and_register` (1) checks that `registry.dir` lies OUTSIDE `run.experiments_dir` (the command line also checks it before any experiment is made; exit code 2), (2) reads the baseline Val result and the finalists, (3) wraps the Test evaluation in ONE `TestOnceGuard` per experiment and gives it to the Selector, which asks for the Test only for the winner and the baseline and never when the baseline stays; the Test split (`pipeline.test_split`) can be scored only through this path (every other path refuses it); the look is also kept ON DISK so that a rerun cannot look twice: `reports/test_once.json` lists the models whose Test evaluation was started (written BEFORE it runs) and `reports/test_result_<baseline|trial_T>.json` holds the finished result, which a rerun returns instead of evaluating again, (4) writes `reports/selection.json`, `selection_table.csv` and `selection_reason.txt`, (5) fills the model card (the fingerprints of the prepare stage, the base model, `exp_NNNN/config_full.yaml`, the library versions, the seed, the code version, the time) and registers it with the review list; an experiment that is already in the registry is not registered again. The verdict of the run is the Selector's; `baseline_retained` is exit code 0. Exit codes: 2 config (also a registry inside the experiments, `finalist_repeats` above 1, a missing baseline result), 4 `SelectorError` (also a second look at the Test), `RegistryError`, evaluation or training failure, 5 `RegistryVerifyError` (a registered model does not match its checksums), 130 stopped. NOTHING IS DELETED (owner rule, DECISIONS 56): the registration request names no finalist folder, so the registry removes no finalist and no checkpoint; only the winner's model folder MOVES into the registry (`registry.transfer`, default `move`: a rename on one drive; across drives a verified copy and then the deletion of the source, see O91). After a registration the winner's model is at `registry/model_NNNN/model`, no longer in `candidates/`. `python -m stt registry list|verify [model_0001]|rebuild-index` reads the registry folder (the config needs only the `registry` section; `--set registry.dir=...`): `list` and `verify` change nothing, `verify` exits with 5 on a mismatch and repairs nothing, `rebuild-index` is the only action that writes (never done silently). The finalist folders and checkpoints use disk space (O86: keep everything; a future `cleanup` may only propose).

## T Standalone tools
- Status: built (Step 0 and Wave 3 task 6, DECISIONS 73; `make_manifest` waits for the owner's approval): `fetch_model`, `fetch_data`, `fetch_wheels`, `make_test_model`, the extra `inspect_audio` and `make_manifest`.
- Purpose: Prepare, outside the pipeline and with network access allowed ONLY here, everything the offline pipeline needs: models, data, packages, the tiny test model and the code manifest.
- How to use (project root, project virtual environment active; every script has a "How to run" header):
  - `python tools/fetch_model.py --repo openai/whisper-tiny --out models/whisper-tiny`
  - `python tools/fetch_data.py --repo <dataset> --dry-run` (prints the size, downloads nothing), then `python tools/fetch_data.py --repo <dataset> --out data/daf_yomi_raw`
  - `python tools/fetch_wheels.py --requirements requirements.txt --out wheels --lock requirements.lock` (add `--python-version 3.12 --platform win_amd64`; the Python running it must be that version)
  - `python tools/inspect_audio.py --data data/daf_yomi_raw` (read-only report on a downloaded parquet dataset: schema and row counts from the metadata, metadata distributions, `entry_id` overlap between splits, about 50 real audio rows decoded, about 30 raw labels with simple counts; options `--seed 0 --audio-samples 50 --text-samples 30`; changes nothing; this tool is an addition requested by the owner, not in the PRD tool list)
  - `python tools/make_test_model.py --tokenizer-from models/whisper-tiny --out tests/assets/tiny_whisper` (builds the tiny random-weight test model with the REAL tokenizer and extractor files, 3.9 MB, loads it through the ModelLoader and runs a forward pass; `--seed 0`, `--force` to replace; already built and stored with the tests, so you only run it again to change the model)
  - `python tools/make_manifest.py --root . --out MANIFEST.sha256` writes the manifest (a `<sha256>  <path>` line per file, sorted, deterministic; local and runtime folders, `.env`, caches and the manifest itself are left out; `--exclude PATTERN`), and `python tools/make_manifest.py --root . --verify MANIFEST.sha256` verifies a tree (exit code 1 for a CHANGED or MISSING file; a file not in the manifest is only listed as EXTRA). `python -m stt check` finds the manifest and prints the code version with `+<8 characters>`; it does not verify the files yet (O109). Make the manifest from the very folder you copy. Tests: `tests/test_make_manifest.py` (15 tests).
  - Run the tool tests: `python -m unittest discover -s tests -v`
- Inputs and outputs: see the brief in `docs/PRD.md`. `fetch_model` and `fetch_data` write the folder plus `fetch_info.json`; they are idempotent (a finished folder is reused, an unfinished one is rebuilt). `fetch_wheels` writes `wheels/` and `requirements.lock`. Exit codes: 0 OK; 1 failure; `fetch_wheels` also 2 = a wheel is missing for the target, 3 = the offline install test failed.
- Known limits: only public repositories (anonymous download). `fetch_model` downloads only safetensors weights and the small config and tokenizer files. `fetch_wheels` takes only binary wheels (`--only-binary`), so a package that exists only as source fails with the package name. The offline install test runs on the home machine, with the same Python version as the target.
- Tests: `tests/test_tools_fetch.py`, `tests/test_fetch_wheels.py` (network faked), `tests/test_inspect_audio.py` (tiny synthetic parquet), `tests/test_make_test_model.py` (the stored tiny model is rebuilt from itself).
